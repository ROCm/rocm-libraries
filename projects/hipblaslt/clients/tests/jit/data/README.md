# Pre-generated JIT test kernels

Each directory under an architecture, `gfx942/` or `gfx950/`, holds generated
kernel sources for that processor. Only the generated sources are committed,
not a library entry. `jit-publish` (`library_writer.cpp`) builds the committed
assembly for the current device and publishes its solutions into the JIT
solution library, so the JIT tests need neither Python nor a generator. Adding
an architecture needs only its `plain` sources.

| Sources | Problem and execution policy | Generator command |
| --- | --- | --- |
| `<architecture>/plain/sources/<kernel>.s` | FP16 A, B, C and D, FP32 compute, A and B not transposed; one wave64 per 16x16 tile, K in steps of 16, no prefetch; GlobalSplitU=1, TileProcessingStrategy=None | `python -m Tensile.SingleSolution ../clients/tests/jit/data/plain.yaml OUT --architecture <architecture> --cxx-compiler amdclang++ --source-only` (`OUT/bundle`) |

The assembly is TensileLite output (MIT licence), generated by the command
above from `plain.yaml` in this directory and the TensileLite sources at
revision `9118578c6b99df2f39ac474ef42807ff518685ef`. One recipe serves every
architecture. The command runs in `projects/hipblaslt/tensilelite` with `OUT`
a fresh directory and `PYTHONPATH` naming the `tensilelite/rocisa` and
`tensilelite` directories of a hipBLASLt build and then
`projects/hipblaslt/tensilelite`. Copy only `sources/*.s` from `OUT`, then
remove the generator's comment and blank lines outside the metadata block:

```bash
sed -i -e '/^\.amdgpu_metadata/,/^\.end_amdgpu_metadata/b' -e '/^[[:space:]]*$/d' \
  -e '/^[[:space:]]*\/\*.*\*\/[[:space:]]*$/d' sources/*.s
```

The assembly is unchanged: `llvm-mc` output is the same before and after. The
metadata is kept verbatim, including the `custom.config` block that holds the
kernel's complete TensileLite solution state. The build does not run either
command.

The assembly is stale when the `KernArgsVersion` or `PersistentLoopArgsVersion`
in it differs from the one in
`tensilelite/tensilelite/Common/GlobalParameters.py`, or the code-object version it
was generated for differs from the version the JIT builder uses. Regenerate it
with the change that made it stale.
