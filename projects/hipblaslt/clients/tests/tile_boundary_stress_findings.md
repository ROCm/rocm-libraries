# Tile-boundary StreamK stress - discovery findings (ROCM-26298 hardening)

This records the discovery run of the tile-boundary stress suite generated by
`generate_tile_boundary_stress.py`. It is a point-in-time result; regenerate and
re-run on any build to refresh it.

## Build under test

- hipBLASLt **1.4** built from source on this branch's tree
  (`git 936a6c7b9e4-dirty`), `GPU_TARGETS=gfx950`, Release.
- Device: AMD Instinct MI350X, `gfx950:sramecc+:xnack-`.

## Method

Three complementary legs, each launched **one isolated process per case** so a
hard GPU fault cannot poison the HIP context and mask later cases
(`run_tile_boundary_stress.py`). All detection relies on the `hipblaslt-test`
NaN guard-pad check (runs at teardown regardless of `norm_check`/`unit_check`)
plus hard-fault/crash detection; `hipblaslt-bench` was confirmed to **mask**
these overruns (it over-allocates), so detection must live in the gtest client.

1. **Leg A - heuristic, K=2048** (`algo_method 0`, `norm_check`): drives normal
   solution selection across the boundary sizes.
2. **Leg B - integer_exact, K<=256** (`unit_check`, bitwise): correctness on the
   same boundary sizes.
3. **Pinned-SK hunt, K=2048** (`algo_method 2`, build-resolved SK indices from
   `resolve_sk3_pinmap.py`): pins the StreamK kernels directly, because the
   heuristic rarely selects them (see below) - this is the leg that actually
   exercises each SK kernel's store edge in the degenerate `tiles == skGrid`
   regime.

## Results

| leg | instances | PASS | FAIL | GPU_FAULT | TIMEOUT |
| --- | --- | --- | --- | --- | --- |
| A+B (heuristic + integer_exact) | 750 | 747 | 0 | 0 | 3 |
| Pinned-SK large-K hunt | 1500 | 1485 | 0 | 0 | 15 |

All TIMEOUT cases (90 s under `--jobs 6`) **passed in ~1 s when re-run serially**
- they are parallelism/HIP-init contention artifacts, not hangs or faults.

**No out-of-bounds store, guard-pad corruption, or wrong-numerics was observed
on the develop build across the entire enumerated tile-boundary space.**

## Key finding: ROCM-26298 is fixed on develop (1.4); still present on 1.3

Ground truth was established with the standalone reproducer from the original
investigation (heuristic top-1, the PyTorch path):

- **System hipBLASLt 1.3 (`100300`, `git f664f44c90`)**: the original fault
  reproduces - `N=2096` and `N=2078` (M=2816, K=2048, T/N bf16) raise
  `hipErrorIllegalAddress`. The trace shows the overrunning kernel is
  `Cijk_Alik_Bljk_BBS_..._MT128x192x128_MI16x16x1_..._SVW8_SK3_..._WG16_16_1`
  with `skGrid = skTiles = 242` - i.e. the degenerate data-parallel StreamK
  regime on a partial N macro-tile, exactly as root-caused in ROCM-26298.
- **Develop build hipBLASLt 1.4 (`100401`)**: the fault does **not** reproduce.
  - Heuristic at `N=2096` passes.
  - Pinning **all four** `MT128x192x128 SK3` variants
    (indices 17499 / 18543 / 18800 / 19057 on this build) at `N=2096`, K=2048
    passes with no guard corruption.
  - The broader pinned-SK hunt (1500 instances) is clean.

Note the heuristic on 1.4 selects a non-StreamK kernel for the ROCM-26298 size,
so the heuristic legs alone are weak evidence; the **pinned-SK hunt is what
confirms** the overrunning kernel itself no longer overruns on develop.

## Disposition

- **Nothing to quarantine.** No `known_bugs.yaml` entry is added by this work;
  the suite is green on develop.
- The suite is retained as **regression coverage** (category `stress`,
  on-demand) to catch reintroduction of this StreamK partial-tile store-edge
  family. The committed legs (A heuristic, B integer_exact) are portable; the
  pinned-SK hunt is regenerated per build via `resolve_sk3_pinmap.py` +
  `generate_tile_boundary_stress.py --pin-map ... --pin-hunt-out ...`.

## Reproduce

```
# 1. Build hipblaslt-test (clients) on a gfx950 box.
# 2. Small stress-only data for fast isolated startup:
python3 hipblaslt_gentest.py -I ../common/include data/matmul_stress_gtest.yaml -o stress_only.data
# 3. Heuristic + integer_exact sweep:
python3 run_tile_boundary_stress.py --binary <build>/clients/hipblaslt-test \
    --data stress_only.data --report findings_AB.md --csv ab.csv
# 4. Pinned-SK large-K hunt:
python3 resolve_sk3_pinmap.py --bench <build>/clients/hipblaslt-bench --out sk3_pinmap.json
python3 generate_tile_boundary_stress.py --logic-dir <.../Logic/asm_full/gfx950> \
    --out /tmp/x.yaml --manifest /tmp/x.md --pin-map sk3_pinmap.json --pin-hunt-out hunt.yaml
python3 hipblaslt_gentest.py -I ../common/include -I data hunt.yaml -o hunt.data
python3 run_tile_boundary_stress.py --binary <build>/clients/hipblaslt-test \
    --data hunt.data --filter '*hunt*' --report findings_pinned.md --csv pinned.csv
```
