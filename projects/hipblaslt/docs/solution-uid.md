# Solution UID foundation

`SolutionUID` is a stable 64-bit identifier for a hipBLASLt/TensileLite
solution. This first migration step provides the identifier format and
maintenance tooling, but does not assign or consume UIDs in library generation
or at runtime.

Geko assigns a fresh UID to solutions copied into `final_libs` or `full_libs`,
including copies from Origami. These are new records, even when they describe
the same GPU kernel. `TensileMergeLibrary` matches `SolutionNameMin`. A matching
name keeps the pooled Equality solution and ignores the incoming UID. The merge
also claims a UID for every solution copied from the base file into the output.
A base UID that is already unique and non-zero is kept. A base UID that is
missing, zero, malformed, or duplicated inside that base file is replaced in
the merged file. The input file is left unchanged unless the output path is
that file.

## Identifier format

```text
| 40 bits: milliseconds since 2026-01-01 UTC | 24 bits: OS randomness |
```

UIDs are generated by
`tensilelite/tensilelite/SolutionIdGen.py`. Internally, a UID remains an
unsigned 64-bit integer. Human-readable files and command-line output use an
unpadded base62 representation:

- the frozen alphabet is `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`;
- writers use the `0u` prefix; readers also accept `0U`;
- leading zero digits are forbidden, except that zero is written as `0u0`;
- values larger than `2^64 - 1` are rejected.

For example, decimal UID `200` is represented as `0u3E`. A UID is stored as
the optional, unquoted `SolutionUID` field immediately after the local
`SolutionIndex` in dict-format logic YAML:

```yaml
- SolutionIndex: 0
  SolutionUID: 0u3E
```

YAML readers decode the text immediately and all identity, comparison, and
mapping operations use the unsigned 64-bit value. New dict-format files from
LibraryLogic (tuning) and TensileMergeLibrary keep `SolutionUID` immediately
after `SolutionIndex`. Legacy list-format files keep keys in their existing
alphabetical layout, so `SolutionUID` follows `SolutionNameMin`.

## Regenerate a UID

To replace one solution's UID after a duplicate is reported:

```bash
cd projects/hipblaslt/tensilelite
python3 -m tensilelite.TensileGenerateUID path/to/logic.yaml --index 5 --inplace
```

`--index` is the solution's local `SolutionIndex` in that YAML file. Without
`--inplace`, the command prints the new canonical `0u` UID without modifying
the file.

One Tensile process and one Geko generation each replace a zero, malformed, or
colliding UID in the files that run writes. `TensileMergeLibrary` writes its
output, and that output replaces a missing, zero, malformed, or colliding UID on
every solution it contains, including solutions copied from the base file. A
unique non-zero base UID is kept. Uniqueness across the shipped logic tree is
checked by `test_solution_uid_uniqueness.py` in the logic-corpus lane
(`tox -e logic-corpus`).

Runtime metadata, runtime selection, and mandatory uniqueness are introduced
by later migration steps.
