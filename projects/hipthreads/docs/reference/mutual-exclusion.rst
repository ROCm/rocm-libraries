**************************
Mutual exclusion API
**************************

hipThreads provides spin-based mutual exclusion primitives for device-side GPU code.
``hip::spin_mutex`` uses spin-wait semantics without OS sleep.
``hip::lock_guard()`` offers scoped RAII locking.
``hip::unique_lock`` provides flexible lock ownership management compatible with ``hip::condition_variable_any()``.
For background on how these primitives fit into the hipThreads synchronization model, see :doc:`/conceptual/synchronization-primitives`.

Spin mutex
**********

``hip::spin_mutex`` is the device-side mutex type.
It uses spin-wait semantics.
A wthread attempting to acquire the lock polls in a tight loop rather than yielding to the OS.
This is appropriate for GPU execution where OS-level sleep is unavailable.

Lock guard
**********

``hip::lock_guard`` is an RAII wrapper that acquires a mutex on construction and releases it on destruction.

Unique lock
***********

``hip::unique_lock`` provides deferred and transferable lock ownership.
It is the lock type accepted by ``hip::condition_variable_any()`` wait functions.
Timed locking with ``try_lock_for()`` and ``try_lock_until()`` isn't enabled in the current release.
See :doc:`/reference/condition-variables` for the condition variable API.
