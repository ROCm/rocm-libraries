# gfx1201 → gfx1250

Both are wave32 WMMA. That is the **only** safe shared assumption. gfx1250 is
a CDNA product on GFX12, not RDNA4. Do not alias the `gfx12_rdna` backend.

## Required changes

1. **Atom K.** gfx1201 f16 is 16×16×16; gfx1250 is **16×16×32**. Fragments
   become `<16 x half>` with a lane-half K split. Copying a gfx1201 A/B pack
   produces a wrong GEMM (`pattern-wmma-lane-map`).
2. **bf16 ABI.** gfx1250 uses `<16 x bfloat>` directly, not the gfx11
   `<16 x i16>` bitcast.
3. **Async DMA appears.** gfx1201 has no catalog async-to-LDS; gfx1250 does
   (`hw-async-global-lds`). A `mem`-only RDNA pipeline is not the gfx1250
   ceiling.
4. **Waitcnt / LDS.** 64 KiB → 160 KiB; split waitcnt + ASYNCcnt replace
   gfx11 `s_waitcnt`.
5. **fp8.** gfx1250 K=64 WMMA; gfx1201 has iu8/iu4 16×16×16, not this fp8
   atom.

Start from `instances/gfx1250/wmma_gemm.py`, not a gfx1201 file with the
target string rewritten.
