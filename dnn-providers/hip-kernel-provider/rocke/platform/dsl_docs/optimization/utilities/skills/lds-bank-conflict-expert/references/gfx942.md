# gfx942 profile

Select `gfx942` to apply the gfx90a grouping rules to the six supported wave64
opcodes and label the result as `gfx942`.

## Supported requests

Use wave64 with `ds_read_b32`, `ds_read_b64`, `ds_read_b128`, `ds_write_b32`,
`ds_write_b64`, or `ds_write_b128`. Supply one instruction's accesses, with at
most one active access per lane. Addresses and access widths are in bytes.
Align each address to the opcode's full width (4, 8, or 16 bytes), and keep the
full access within the 65,536-byte LDS capacity.

Unavailable opcodes or wave sizes are unsupported. Width mismatches, misaligned
addresses, and accesses beyond the LDS capacity are invalid request data. See
[model-contract.md](model-contract.md) for the complete request and result fields.

## How accesses are grouped

The predictor groups active accesses by lane phase and address class. A lane
phase is a set of lanes considered together for the selected opcode. Accesses
in different phases are considered separately. The address class is the byte
address modulo 128: addresses 0 and 128 share a class, while 0 and 4 do not.

Within a group, accesses to different addresses produce a conflict; reads from
one shared address produce a broadcast. Inactive accesses are excluded from
grouping. Conflict multiplicity counts the accesses in the reported group.

For example, `ds_read_b32` accesses from lanes 0 through 3 at byte addresses
0, 128, 256, and 384 produce one conflict group with multiplicity 4. Changing
the addresses to 0, 4, 8, and 12 produces no conflict groups. Lanes 0 and 32
belong to different phases for this opcode, so accesses from those lanes at
addresses 0 and 128 also produce no conflict group.

## Validation boundary

Within these six opcodes, gfx942 and gfx90a use the same prediction rules and
retain separate profile identities. CPU tests check the implementation against
expected classifications and group membership. They do not establish current
hardware behavior, physical bank organization, or execution time. See
[validation-boundaries.md](validation-boundaries.md) before interpreting results.
