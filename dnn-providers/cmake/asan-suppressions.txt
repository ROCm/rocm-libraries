# AddressSanitizer runtime suppressions for hipDNN tests.
#
# Keep this file in sync with projects/hipdnn/cmake/asan-suppressions.txt. The two
# trees configure independently (dnn-providers can build standalone), so each
# needs its own copy.
#
# ONLY interceptor-detected errors can be suppressed here. ASan supports
# interceptor_name, interceptor_via_fun, interceptor_via_lib and odr_violation
# and nothing else — a direct instrumented load/store cannot be suppressed.
#
# ---------------------------------------------------------------------------
# rocBLAS/Tensile lazy library-load data race
#   AIBTINFRA-48 · https://github.com/ROCm/rocm-libraries/issues/8869
#
# A lazily-loaded Tensile placeholder library is read on T0 (findBestKeyMatch,
# a 32-byte key compare via the memcmp/bcmp interceptor) while an std::async
# loader thread spawned from TensileHost::get_library_and_adapter deserializes
# into the same matching table and reallocates its backing vector.
#
# The race fires on first GEMM activity for a problem class and is NOT specific
# to any operation: all three convolution directions reproduce it identically
# (14/14 isolated runs). It is upstream library code, not hipDNN, and it is
# equally present in non-ASAN builds where nothing detects it.
#
# VERIFICATION: placebo-controlled A/B on gfx90a, same build and seeds.
#   no ASAN_OPTIONS ............................. crash 2/2
#   suppressions file matching nothing .......... crash 2/2
#   print_suppressions=1, no file ............... crash 2/2
#   this pattern ................................ clean, 138/138 twice
#   interceptor_via_lib:librocblas.so ........... clean, 138/138
# The crash point is seed-determined (seed 401 at test 1, seed 402 at test 13,
# identical across all three non-suppressing arms), so the clean runs are not
# luck. Having a suppressions file present is not itself sufficient; only a
# pattern that can match prevents the abort.
#
# ⚠️ Caveat: print_suppressions=1 nonetheless reported a tally of ZERO on the
# clean runs. The causal claim rests on the placebo control, not on the tally,
# and that discrepancy is unexplained. If this entry is ever edited, re-run the
# placebo A/B rather than trusting the tally to reveal a broken pattern.
# See Research/ALMIOPEN-2673-tensile-trigger-experiment.md.
interceptor_via_fun:*findBestKeyMatch*

# Fallback, deliberately NOT enabled: this suppresses every interceptor-detected
# error arriving from librocblas, which would also hide genuinely new rocBLAS
# memory bugs. Enable only if the narrow entry above proves unmatchable.
# interceptor_via_lib:librocblas.so
