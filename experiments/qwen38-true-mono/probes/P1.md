# P1: real-layer stacks and the cross-layer hand-off (DESIGN 8.2 / 3.2)

Status: **done 2026-10-31 (W2). The DESIGN gate is NOT met:** no arm wins per layer against graph-launched single
mono layers on `best` (or `numa`), in any form that was built (unrolled 2- and 4-layer stacks, and a runtime layer
loop at depth 1-8). Numerics are fully met: every `xl` arm is bitwise equal to the single launches. Every mutant
fails the gate, and the no-fence diagnostic arms fail it as they must.

The answer D0 needs is still clear, and it is not "the hand-off loses":

- **The in-kernel hand-off is cheaper than a graph boundary.** With identical code, an in-kernel `xl` hop costs
  0.02-0.08 of a layer less than the launch boundary of the same kernel.
- **What loses is code.** An unrolled stack runs each layer on its own copy of the code, which is a cold
  instruction stream; a runtime loop pays P6's recipe (fresh ids, per-stage argument reloads).
- **As built, Path A's per-layer cost at full depth** (asymptote of the loop) is:
  - delta r1: 1.012-1.023 of a graph-launched layer;
  - delta r4s: 0.999-1.013;
  - qsa r4s: 0.997-1.001.

Ratios only; absolute per-layer times are in `hackathon-prep/private-perf/qwen38-true-mono/probes/P1.md`
(raw: `P1-raw/`). Below 1 is faster.

## 2. What was built

`p1_stack.py`: three builder families, each taking ATOM's FlyDSL layer bodies as they are (`kernel._run`, the
`stages/*` functions):

- **`build` (unrolled `depth`-layer stack, depth 2-8)**, generalizing `kernels/stack.py`:
  - **Layer arguments and scratch.** Layer k >= 1 takes its arguments from a device table, and consecutive layers
    alternate between two scratches (or one: `onescr`).
  - **Hand-off arms (`hand`):**
    - `fence` (stack.py's release / acquire, a);
    - `nofence` (b, not correct);
    - `xl` (c / d / e).
  - **The `xl` hand-off, producer side.** `m5_x` is a copy of `moe.m5` plus the publish into the next layer's scratch
    regions `ph` / `phs`, with the next layer's tag: the PLE layer's P2 -> A1/A2/C1 layout, unused by delta / qsa
    layers. It publishes the layer output words as pairs and their 16-column square sums in C1's `whs` tree. NUMA dual
    copies when `numa` is on.
  - **The `xl` hand-off, consumer side.** A1 and A2 run ATOM's polled HC path on it; C1 (`c1_x`, a copy of
    `out_proj.c1`) polls its residual word.
  - **Knobs:**
    - `xhold` = layer / xpre / none, with an optional poll backoff (`xpause`);
    - `late` = pairs / bulk;
    - `pol` = 3 (remote copy);
    - `argrl` = R1 / R2 / both (P6's rules);
    - `a1hf`: A1 streams-first (`_a1_task_hf`, a copy of `hc._a1_task` with the polled branch reordered: poll, then
      barrier, then the down weights);
    - next-layer knobs (`bsched`, `bdelay`: holds and delays re-anchored at the hop);
    - Coz points (`leave`, `enter0`);
    - mutants (`mut` = xlval / xlhs).
- **`build_loop` (runtime layer loop, depth 1-8):** one traced layer body in an `scf.for` over the layers.
  - **Recipe.** P6's R1 (every argument reloaded per stage from the layer's table row), R2 (fresh thread / block ids
    per iteration), R3 (only the layer index carried) and R4 (`-disable-machine-licm`, through FlyDSL's
    `compile_hints`).
  - **Runtime branches.** Layer 0 reads `h_in` (a runtime branch on k == 0 around A1/A2/C1); the M5 publish is
    skipped on the last layer (a runtime branch).
  - **Knobs:** `xhold`, `a1hf`, `leave`, `enter0`, `fid` (R2 off), `mut`.
  - **Evidence that the body is traced once.** A qsa r4s depth-4 loop traces in 22 s locally, against 120 s for the
    unrolled build.
- **`monoN`** (in the rig): the profile's single layer as N distinct code objects (`pause.<stage>=0` knobs: the same
  IR under another kernel name), launched round-robin. This is the code-temperature control.

## 3. Numerics (before any timing, same process; DESIGN 9.1)

Per family and arm, group 0 is run from one snapshot and compared with the profile's graph-free single-layer
sequence. The comparison covers:

- every layer's output;
- the DeltaNet conv / recurrent pools;
- the QSA caches of every copy;
- the last layer's mailboxes. Stacks use their own scratch; the `xl` regions `ph`/`phs`/`pk` are excluded there,
  since they carry the hand-off. NUMA copy 1 must equal copy 0.

Each arm also gets a second run (determinism) and a nonzero-output check.

- **All `xl` and fenced arms, unrolled and loop:** bitwise and deterministic, in every family of every round and
  job.
- **`mono_rc`:** bitwise too.
- **`b` / `bRF` (no fences):** not bitwise (stale `h_in` words), sometimes not deterministic. They are timed as a
  diagnostic only; their numerics are never gated.
- **Mutants:** each must differ, and all do in every job:
  - `mutate.c1` on `cRF`, `aRF` and the loop;
  - `xlval`, the `xl` payload with bit 0 flipped while `h_out` stays right: proves the next layer really consumes the
    hand-off, unrolled and loop;
  - `xlhs`, the published square sums doubled: proves A2's norm uses them.

## 4. Timing (DESIGN 9.1)

Set-up and discipline:

- Graph replays of 96 layer launches' worth (16 cold weight copies, context 8192, synthetic weights, `MonoRig`);
  per-LAYER time.
- 30 rounds with the arms in a seeded shuffled order and 5 replays each; per-round ratio vs that round's `mono`.
- Two controls: `mono2` (second graph) and `mono_rc` (separately compiled). Control bands stay within
  0.993-1.005 in every family.
- WIN / LOSS: median past both controls' extremes by 0.002 AND >= 3/4 of rounds.
- Unstamped builds.
- Clocks sampled every second; no round was throttled (p6f's rule: a busy sample > 3% below the process's median

- Every arm-vs-arm pair below is gated per round the same way.

## 5. Reading the loop model

r(D) = x + y / D with:

- x = per-layer cost of a layer behind an in-kernel hop (the pass in one launch);
- x + y = r(1), the same loop body launched once per layer (graph boundary + the kernel's entry);
- y = (launch boundary + entry) - (in-kernel hop), with the same code.

What the fits say:

- **y > 0 in all 72 fitted cells (both jobs).** The hop is always cheaper than the launch: 0.02-0.06 of a layer on `best`, up to
  0.08 on `numa`.
- **The loop body is the cost.** r(1) - 1 = 0.024-0.078: the loop body with a graph boundary per layer is that much
  slower than the hybrid's single-layer body. This is the FlyDSL-level loop recipe: R2's recomputed index math,
  per-stage table reloads, the k == 0 branch, and no `a1_preload` hoisting.
- **The two cancel to within a few percent.** x = r(1) - y.

So the D0 question "is the in-kernel hand-off at or below the graph boundary per layer?" is answered yes for the
hand-off (y > 0, both nodes, every seed). The layer-level gate fails on the body.

The same reading explains the unrolled stacks: they avoid R2's cost but pay the cold-code cost (`monoCN`), which
is of the same size (1.0-4.9%).

## 6. Non-bitwise variant (user decision 1): analysis, not built

The rev 3 candidates that touch the cross-layer hand-off are N9 = N1c (the `xl` payload carrying the M5-epilogue
partial down-projections, so that A1 becomes a 20-CTA reducer) and N1b (norm after GEMV, so that A1 starts per-stream
partial dots as stream tiles land instead of waiting for all 160 producers). P1's data say where they would act and
bound them:

- **The hop is not the bottleneck.** y > 0, the payload is already minimal (bf16 words in pairs), and no format of
  the hand-off itself (fewer bits, fewer pairs) is cheaper in a way the data point to. The fences (bitwise
  protocol) and the code are where the time went.
- **A1 is the critical path behind every hop.** Its entry slope is 0.77-1.08, and its tail (the 4-stream norm, the
  pack, the down chain) is what N1b / N1c remove. That is DESIGN 12.3 N1's share (a1 + m1 incr 0.17 / 0.23 of a
  round; booked 0.016 / 0.020).
- **Why it was not built here.** Building it needs the tolerance machinery that does not exist yet: P11's T0-T2
  thresholds and P3x's in-situ FlyDSL variants. Without them a timed non-bitwise arm could not be accepted or
  rejected. **It stays with P3x / WP15**, with this probe's loop rig (`p1_rig.py`, round 4) as its in-situ timing
  harness: N1b / N1c change A1, which is exactly what x and the A1 slope measure.

## 7. Limits and open items

- **Rig.** Synthetic weights at context 8192 with 16 cold copies, as `sched_rig` / `stack_rig`; graph-replayed
  layers on the hybrid's FlyDSL bodies, not rocKE bodies. The per-layer ratios are the hand-off's; they are not e2e
  numbers.
- **Same-kind stacks only.** No delta -> qsa / qsa -> delta transitions, which the 3:1 pass has, were built. The
  delta_ple layer and P2 as an `xl` consumer were not built either (delta_ple uses `ph` for its own P2; the `xl`
  region for it would move to `isc`). The plan's "`xl` to A1/A2/C1/P2 incl. `xl_late=bulk`" is therefore covered for
  A1/A2/C1 only. The P2 edge is one hop per pass.
- **Holds were sampled, not climbed:**
  - head sleep 0 / 256;
  - no stage holds on later layers;
  - run-ahead holds of 32 / 64 / 128 units;
  - an xhold poll backoff of 4 units.

  The climb belongs to WP3, on the rocKE bodies.
- **Unresolved Coz and timelines.** qsa r4s Coz slopes are below resolution (section 1 item 5). No stamped
  timelines or WaveScope captures were taken, so the A1 critical-path claim rests on Coz slopes plus the `H` / `xpre`
  results.
- **Neighbours.** The node's neighbour list was printed from inside the container, where `squeue` does not exist
  (recorded in the alola skill, rule 159), so neighbours per row are not logged. All control bands stayed within
  0.993-1.005, and the directions agree across both nodes and five seeds.
- **Cross-pipeline arithmetic.** The P6-recipe projection in section 1 item 1 combines numbers from a different
  build pipeline and different jobs. It is an estimate for D0's decision rule, not a measurement.
