# Probe P6: code size, compile time and registers of the real layer bodies in one persistent kernel (DESIGN 8.2)

Status: **done 2026-10-30 (W2). Gate met** for the inline design: with the in-loop recipe (section 4), every module
(the real qsa r4s and delta_ple r4s bodies, NUMA on, in a runtime layer loop; the target pass; the whole K=3 round
with its head; the K=0 round; the widest round) has no VGPR/SGPR spill, no scratch, and no exec-join finding. The
`noinline`-per-layer-body variant fails the gate on every module (scratch from the callee-saved register frame) and
loses heavily on hardware. **Decision recorded: inline every layer body.**

**Fix round (2026-10-30, after the verifier's PARTIAL).** The per-call cost of `noinline` depends on the layer
hand-off. Section 1 now gives the corrected figure: about **0.12-0.16 hybrid units per K=3 round and 0.18-0.24 per
K=0 step** with a mailbox-like hand-off, not 0.46-0.49 / 0.64-0.73. Every timed arm is now bitwise on both nodes. The
DESIGN 9.1 deviations are removed. Rule R4 is timed on hardware for every body of the rounds and for both heads.
See the "Fix round" section at the end for the details.

Numerics were checked on hardware before any timing, in the same jobs, on both rocke nodes. Each run compared 0.65 GB (delta_ple r4s) or 1.35 GB (qsa r4s)

## 1. What D0 gets from P6

1. **Inline vs `noinline` per layer body: inline.**
   - A real call per layer body forces the callee-saved register frame of the C calling convention. On these
     at-limit bodies that is 296 B (r4s), 416 B (qsa r1) and 424-440 B (wide) of scratch per lane per call. IPRA
     (`-enable-ipra`) does not remove it.
   - That frame fails the "no scratch" gate on every module.
   - On hardware `noinline` loses with every hand-off between layers, on both nodes, in every process (fix round,
     96 launches per replay):
     - no grid sync (each layer its own launch, the closest to WP1's `xl` mailbox hand-off): `On/O1` = 1.105-1.120
       (qsa r4s) and 1.117-1.130 (delta_ple r4s);
     - one-thread-fenced grid sync: `Lnt/Lt` = 1.14-1.18;
     - per-wave-fenced grid sync: `Ln/Li` = 1.23-1.27.
   - **The call's cost depends on the hand-off** (corrected; the first version said it does not). Per call, in
     graph-launched mono layers:

     | hand-off | qsa r4s | delta_ple r4s |
     |---|---|---|
     | none | 0.105-0.121 | 0.120-0.133 |
     | one-thread fence | 0.162-0.182 | 0.192-0.219 |
     | per-wave fence | 0.350-0.373 | 0.421-0.465 |

     These are the table-argument arms. With arguments via LDS the cost falls in the same ranges.
   - Scaled to the served round (51 body calls per K=3 round, 48 per K=0 step, against the hybrid's round and step
     times), the "none" hand-off gives about **0.12-0.16 hybrid units per K=3 round and 0.18-0.24 per K=0 step**.
     The first version said 0.46-0.49 / 0.64-0.73, which is the per-wave-fenced figure. The corrected cost is still a
     decisive loss that no compile-time gain can repay, and `noinline` still fails the scratch gate.
   - `noinline` saves only about 0.7 of the inline module's LLVM time, and it cannot compile bodies separately
     (one codegen unit).
2. **The real at-limit bodies fit the dynamic loop, but only with five rules.** These are DESIGN 6.3's rules made
   concrete, and WP1 must implement all five:
   - **(R1) Per-stage argument reloads** from a read-only per-layer table (scalar loads; ATOM knob
     `ATOM_Q38_ARGSEG=1` for the FlyDSL bodies). Arguments at body entry and held through it fail: 4 SGPR spills and
     68 B scratch on qsa r4s even with the other rules. LDS-staged arguments (`args=lds`) work but buy nothing over
     the table: `Lil/Li` 0.999-1.007, mostly noise. With no grid sync they lose a little: `O1l/O1` 1.006-1.008 on
     delta_ple r4s (fix round). **D0 record:** this changes DESIGN 6.2 ("Default `args=lds`") and the WP1 row
     ("layer table (`args=lds`)") to `args=const` by default, with `args=lds` kept as a knob.
   - **(R2) Fresh hardware ids at every read**: workitem id, workgroup id, lane id (`mbcnt`) and `s_getreg`, through
     an `asm sideeffect` copy, in every body, every rocKE stage function and the head.
     - Without this, LICM hoists all id-derived index math of the stage functions out of the layer loop. qsa r4s
       then has 496 VGPR / 363 SGPR spills and 1476 B of scratch.
     - With it, the scratch is 0.
   - **(R3) Loop-carried state = the schedule index only.** The driver re-reads its own arguments per iteration.
     Holding them costs 8 SGPR spills on qsa r4s.
   - **(R4) MachineLICM off** for the round module (`-disable-machine-licm`). It hoists constants out of the outer
     loop: 28 SGPR spills on qsa r4s, 116 on delta_ple r4s.
     - **R4 itself is free on hardware** (fix round, every body of the rounds plus both heads, both nodes). A
       standalone layer compiled with MachineLICM off (`R4`) runs at 0.994-1.008 of the same IR compiled with it on
       (`relink`). That is noise in 118 of 120 process-runs over 10 bodies (one WIN at 0.995, one LOSS at 1.005).
       The head with R4 runs at 0.997-1.005, noise in 18 of 18.
     - **The recipe's cost is R2 (fresh ids)**, not R4. R2 alone (`R2`) costs the same as R2 + R4 (`Rr`), relative
       to `relink`: 1.005-1.013 (qsa r4s), 1.017-1.019 (delta_ple r4s), 1.016-1.018 (delta r4s), 1.019-1.030 (qsa
       r1), 1.027-1.030 (delta r1), 1.011-1.014 (delta_ple r1), 1.010-1.021 (qsa r4). On the heads R2 costs
       1.004-1.011 (LOSS in 8 of 18). The r16g4 bodies pay at most 0.8% for R2 alone and nothing for R2 + R4
       (0.994-1.001).
     - The first version's "`Rr` runs at 0.997-1.007 of the mono (qsa r4s, noise)" compared against the mono, which
       is itself about 0.99 of `relink` on qsa (R1 wins there). Against `relink`, `Rr` is 1.008-1.018 on qsa r4s.
     - MachineLICM's sink-to-avoid-spills mode (`mlicm=sink`) still spills (26 / 104 SGPR spills).
   - **(R5) Workgroup id via an LDS word** written once at launch. The hardware SGPR is otherwise live across the
     whole loop: the K=3 and K=0 rounds kept 1 SGPR spill without R5. Reading it from LDS costs nothing measurable:
     `Lb/Li` 0.994-1.003, noise.
3. **The loop module's body code runs as fast as the standalone layer** (arm O1 = the loop module launched once per
   layer, no grid sync):
   - qsa r4s: 1.005-1.009 of the mono (two runs noise, one a 0.9% LOSS);
   - delta_ple r4s: 1.022-1.024 of the mono (the R1 + R2 + R4 cost).
   - Fix round, every round body: `O1` vs the mono is 1.002-1.008 (qsa r4s), 1.023-1.025 (delta_ple r4s), 1.026-1.030
     (delta r4s), 1.031-1.044 (qsa r1), 1.043-1.047 (delta r1), 1.016-1.027 (delta_ple r1), 0.997-1.007 (qsa r4),
     1.002-1.005 (qsa and delta_ple r16g4) and 1.011-1.014 (delta r16g4).
   - **The decode bodies (r1) pay 1.6-4.7% per layer** for the recipe, mostly R2 (above) plus about 1.5% for the loop
     module's own code. That is a K=0 cost that WP1 / RSI must claw back (section 7).

   So the dynamic loop itself adds nothing beyond the recipe's code cost. What it costs is the layer hand-off
   (item 4).
4. **Hand-off warning for P1 / WP1: a fenced grid sync is the wrong hand-off.**
   - A grid sync between layers where every wave does an agent release (`buffer_wbl2 sc1`) and an agent acquire
     (`buffer_inv sc1`) makes a layer 1.51-1.53x (qsa r4s) and 1.68-1.72x (delta_ple r4s) of the mono. That is about
     +0.52 / +0.66 of a layer.
   - Doing the fences on one thread per CTA (`Lt`) still costs 1.16-1.18x / 1.22-1.23x.
   - It matches P4 (fenced/bulk hand-offs lose) and DESIGN 4 (tagged sc1 mailboxes, never cache-wide fences). WP1's
     layer hand-off must be the `xl` mailbox. A cache-maintaining grid sync is acceptable only where it runs once per
     launch.
5. **Compile time is not a constraint for inline** (LLVM part, same pipeline for every module):

   | module | / slowest of its layer kernels | / sum of them |
   |---|---|---|
   | full K=3 round, inline | 5.4 | 1.85 |
   | widest round, inline | 4.8 | 1.77 |
   | K=0 round, inline | 3.7 | 1.74 |
   | target pass, inline | 3.6 | 1.65 |
   | one-body loop | 1.30-1.42 | |
   | noinline rounds | 2.8-3.9 | 1.24-1.32 |

   In absolute terms a whole round compiles within one comgr call well inside the server-start budget (private
   file). Growth is mildly superlinear in the number of bodies. Per-build CPU fan-out (DESIGN 6.4) stays the RSI
   strategy.
6. **Code size and branch reach.**
   - Inline modules:

     | module | code size |
     |---|---|
     | K=3 round | 552 KB |
     | widest round | 980 KB |
     | K=0 round | 319 KB |
     | target pass | 398 KB |
     | one layer body | 92-320 KB |

   - LLVM relaxes 6-27 branches per module into `s_getpc`/`s_setpc` long jumps. All of them are driver-level, once
     per layer, never in a hot loop.
   - Every one-body loop of a narrow body (above 128 KB) already needs relaxation. **The Rust direct compiler needs
     branch relaxation before it can build any loop module** (`research/rust-direct.md` already lists it as a
     blocker).
7. **A free lever for the hybrid as well: `ATOM_Q38_ARGSEG=1`** (R1 on the standalone FlyDSL build).
   - qsa r4s: WIN 0.988-0.996 of the hybrid layer in 5 of 6 process-runs on both nodes (one noise). It also removes
     the qsa r4s build's 2 SGPR spills.
   - delta_ple r4s: LOSS 1.005-1.007. Keep it as a per-kind knob, default off.

## 2. What was built (method)

The true mono's qsa / delta_ple / HC / B1 / C1 / Q emitters do not exist in rocKE yet. P6 therefore uses the **real
bodies at the LLVM level**: the mono layer builds' own IR, in the served hybrid ALL configuration.

- **Layer bodies.** `ATOM_Q38_SCHED=best` (NUMA on for narrow builds) plus the rocKE fused MoE and B3 stage functions
  linked as FlyDSL links them (`--only-needed --internalize`).
  - Each build's kernel becomes a device function (43 parameters plus the row pointer that replaces the kernarg
    segment pointer).
  - All bodies share one LDS arena (the largest build's).
- **Driver.** A driver kernel (256 x 512) runs a device-side schedule: `kind | row << 8` per layer, a switch to one
  wrapper per (kind, variant), and a grid sync with a deadline and an error word.
- **Heads.** For the rounds, the P2 persistent head (`mx_decode_gemv` MXFP4 with fused argmax, 4 waves of 512
  threads, `pairs` at rows 4 / `bulk` at rows 16) is lowered by rocKE as a device function on a window of the
  arena.
- **Compile pipeline.** The container's ROCm LLVM: `llvm-link` -> `opt` (internalize, O2) -> codegen at O2 (code
  object v6; FlyDSL's ROCDL `O=2`) -> `llvm-mc` -> `ld.lld`.
  - Faithfulness check: compiled standalone, every layer build reproduces the FlyDSL binary's VGPR count exactly and
    its SGPR count within 1 (13 builds).
- **Resources.** Resources come from the code-object metadata, plus per-function info from the asm (callee frames)
  and FlyTape's exec-join lint (ported) on every module.
- **Rounds** (DESIGN 6.1):

  | round | bodies |
  |---|---|
  | target pass r4s | delta, delta_ple, qsa |
  | K=3 CONC 1 round | + drafter qsa r4s (same body as the target's) and qsa r1, + head r4 |
  | K=0 round | delta, delta_ple, qsa r1 + head r4 |
  | widest round | delta / delta_ple / qsa r16g4 (draft r16g4 = target body) + qsa r4 + heads r16 and r4 |

| piece | where |
|---|---|
| IR transforms, driver, compile + resources + lint | `hackathon-prep/qwen38/truemono/P6/p6_ir.py` |
| per-configuration build (singles, `loop1@<build>`, rounds; knobs below) | `.../P6/p6_build.py`, `p6_heads.py`, `p6_summary.py` |
| IR dumps of the layer builds (FlyDSL `FLYDSL_DUMP_IR`, compile-only) | `.../P6/p6_dump.py`, `p6_dumpall.sh` |
| GPU rig: numerics gate, mutants, shuffled timing | `.../P6/p6_gpu.py`, `p6_gpu_job.sh` |
| CPU compile fan-out (rocke nodes without a GPU) | `.../P6/p6_cpu.sh`, `q38_job_cpu.sh`, `submit_cpu.sh` |
| CPU tests (15; 3 mutants of `p6_ir.py`, all killed) | `.../P6/test_p6_ir.py` |

## 7. Decision recorded (for D0 and WP1)

- **Inline per layer body** (`alwaysinline` + `convergent` from wrapper to body to stage function), one round module
  per (K, G) variant.
- `noinline` stays a registered default-off knob (`inline=never`). It loses on both the gate and the hardware; keep
  it for cold once-per-launch stages only if those ever push the register max (the heads did not: with R2 the head
  fits).
- WP1's framework implements R1-R5 as defaults:
  - **R1:** the per-layer read-only argument table with per-stage scalar reloads (`args=const`); `args=lds` stays a
    knob.
  - **R2:** fresh-id emission in rocKE emitters (one fresh read per use site of the workitem / workgroup / lane id
    and `s_getreg`).
  - **R3:** the loop carries only the schedule index.
  - **R4:** `-disable-machine-licm` for round modules (a compile option the rocKE compile path must pass).
  - **R5:** the workgroup id in an LDS word.
  - **CI gate:** `.sgpr_spill_count`, `.vgpr_spill_count`, `private_segment_size` and the exec-join lint all 0.
    Every round module of section 4 passes it today.
- **Layer hand-off: tagged `xl` mailboxes (P1).** No per-wave agent fences between layers. A cache-maintaining grid
  sync only once per launch.
- **RSI items:**
  - claw back the recipe's per-layer code cost. The fix round puts it at 1.02-1.03 on delta_ple / delta r4s, and
    1.02-1.05 on the r1 decode bodies (`O1` vs mono), almost all of it from R2;
  - R2 restricted to the stage functions whose id math LICM hoists. This is now the first RSI item: R2 is where the
    cost is, R4 is free;
  - a narrower MachineLICM control than whole-module off (`sink` is not enough). Lower priority, since R4 costs
    nothing measurable.
- **Call cost to quote (D0 / WP1):** a `noinline` body call costs about 0.12-0.16 hybrid units per K=3 round and
  0.18-0.24 per K=0 step with a mailbox-like hand-off (fix round), not the per-wave-fenced 0.46-0.49 / 0.64-0.73.

## 8. Hazards and findings

- **LICM is the dominant spill source in a layer loop, not the bodies.** Hardware-id-derived index math of
  separately written stage functions (here rocKE MoE/B3 and the P2 head) is loop-invariant once inlined into the
  loop and gets hoisted. Fresh ids must be applied to every emitter, including foreign ones.
- **A parameter-level mutant can be inert under R1.** Per-stage reloads read the argument table directly, so
  corrupting the entry parameter (`hin`) changes nothing in builds without an entry preload of that argument
  (delta_ple). Gate mutants for WP1 must corrupt the table rows or the schedule (`rowx`), not the entry parameters.
- **Calls are not cheap on this ISA at these register counts.** The callee-saved frame of a 216-VGPR body is about
  300 B per lane. Every call spills and refills it to scratch for 512 threads x 256 CTAs.
- **Branch relaxation is mandatory above 128 KB of code.** Already one narrow layer body plus the driver crosses it;
  LLVM reserves an SGPR pair for it.
- **FlyDSL's own binaries vary run to run here too** (WP0a rules 130/133): the hybrid qsa r4s build showed 0 or 2
  SGPR spills in different jobs.

## 9. Limits

- **Bodies are FlyDSL's IR, not rocKE ports.** They are the reference shapes the ports must reproduce bitwise, so
  register pressure should transfer; the rocKE emitters' own code is not measured here. The rocKE MoE / B3 / head
  pieces are real rocKE.
- **Hardware timing covers the loop modules of the two at-limit bodies (r4s), every round body standalone and per
  layer (fix round), and both heads.** The rounds themselves are compile-only: the rig has no multi-kind schedule
  with heads.
- **Per-call cost in hybrid units is an extrapolation** from rig layers (16 cold weight copies). It is scratch
  traffic and should transfer, but it was not served. The mailbox hand-off figure uses the no-sync arm (`On` vs `O1`,
  one launch per layer) as a stand-in for P1's `xl` hand-off.
- **The grid sync used between layers is a P6 harness, not a hand-off proposal.** Its cost figures are a warning for
  P1, not P1's answer.
