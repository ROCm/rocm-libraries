# P15: the N3b router form in the hybrid's rocKE fused MoE (gfx950, wave 1)

D0.md section 5, wave 1 group 1a; D0.5 (N3 down-weighted: "only the hop-removing form (N3b: redundant per-CTA
top-10, no route table / barrier) is worth building"), DESIGN 12.3 N3 (b), DESIGN 8.2 P15, plus a router-targeted
must-fail mutant (the P10 gap, `probes/P10.md` 8.5). Ratios, shares and counts only. Absolute times:
`hackathon-prep/private-perf/qwen38-true-mono/wave1/P15.md` (raw JSON and job logs in `P15-raw/`).

Status: **done, gate met; N3b LOSES.** The N3b form is bitwise (no tolerance class needed): every arm equals the plain
FlyDSL mono layer bit for bit in all 6 layer cells, and the new router mutant is caught every time. In-situ layer A/B,
on the served hybrid layer (`best`) and on the quick track's lookback pick, at r1 and r4s, on both rocke nodes: every
N3b arm is a LOSS in every run (1.4-8.1 % of the layer, 0 of 24 rounds faster, every time). Its two mechanisms remove
no hop. N3b's booking goes to 0. The knobs stay as default-off levers, and they are in the lookback pools.

## 1. What D0 gets from P15

1. **N3 (N3b form): book 0 at K=3 and K=0.** (It was 0.0125 / 0.0125 hu in D0 section 2 at p = 0.5.) Layer time,
   N3b arm / its base, both rocke nodes. The ranges cover the four runs (two per node, seeds 0-2):

   | cell | on `best` (the served hybrid layer) | on the quick-track pick (`picksG`) |
   |---|---|---|
   | delta r4s (K=3 verify, 35 of 48 target layers) | **1.066-1.073** LOSS | **1.075-1.081** LOSS |
   | delta r1 (K=0 decode) | **1.023-1.026** LOSS | **1.023-1.028** LOSS |

   Each half alone also loses. On `best`: the router over every CTA costs 1.014-1.018, the per-wave top-10 costs
   1.014-1.019 (r1) and 1.048-1.055 (r4s). On the pick: 1.022-1.040 and 1.014-1.066. The losses add up, and no
   combination of the two halves wins.
2. **Why: neither mechanism removes a hop.** Phase stamps give fractions of the plain mono's MoE increment, past M2's
   end (section 4.3).
   - **The last router task ends at the same time** with 2 router rows per CTA as with 8 (r4s: 0.167-0.169 in both),
     or only 0.01 earlier (r1). P10 found the same for half the rows (w129). The router task is fixed latency: the
     M2 -> M3 hop, LDS staging, a 24-step fma chain and a 16-lane ordered sum. Its bytes do not set its length.
   - **Spreading the router over all 256 CTAs puts a router task on every CTA.** At r1 the median CTA used to run
     none (stamp 0.02) and now runs one (0.16). That delays the shared-expert group, the extras and the gate_up
     issue, and the MoE increment grows by 0.06-0.09.
   - **The per-wave top-10 makes routing finish later**, not earlier: by +0.025-0.03 at r1 and +0.10 at r4s. With
     it, 8 waves (instead of 1 or 4) run the DPP-serial top-10, R times each at r4s, plus their own slot union, on
     the CU's 4 SIMDs. The barrier it removes was only waiting on the routing waves anyway. The null-byte twins move
     the same way (fixed overhead F +0.14 at r4s), so the cost is latency, not bytes.
3. **What is left of N3.**
   - The only form that can remove a hop is **N3a**: the router K-split fused into M2's epilogue. It removes the
     M2 -> M3 hop and the per-task chain. In the hybrid M2 is a FlyDSL stage, so N3a belongs to the true mono's own
     M2 (WP2a/WP2d family). **WP16 should be rescoped to N3a or dropped.** Its p and value are unmeasured, and there
     is no bitwise twin below it (N3b = 0, G6 = 0 from P10).
   - The MFMA variant of N3b (tolerance class) was not built. MFMA would shorten only the 24-step chain, which is
     part of the router task's fixed latency. It would keep the every-CTA router cost (ept2) that this probe
     measured as a loss. On these measurements its expected value is about 0 or below, so it is not worth a
     tolerance-ladder slot.
4. **Router mutant (the P10 gap): closed.**
   - `router_kdrop` leaves K part 15 out of every router logit. It changes the `lg` payload AND h_out in 8/8 cases
     of every cell and run (base and N3b router, 8 cell-runs).
   - `router_ksum` reverses the K-part sum, a 1-ulp f32 change that the logit's bf16 rounding usually hides. Where
     it surfaced in `lg` (4 of 64 case-runs for each router, base and N3b alike, all at rows 4), h_out was bitwise equal in all 4, and only the `lg`
     comparison caught it. So the gate's bitwise `lg` / `sg` check is necessary, not redundant with h_out.
   - `route_k11` (every routing pass takes the 11th pick for the 10th) differs in h_out 8/8 everywhere.
5. **Side finding (hardware): a single-wave routing mutant deadlocks.** The first mutant design let wave 7 alone take
   the 11th pick. At rows 4 (`slots=wave`) it hung the layer on both nodes: the build's first launch never returned,
   and the jobs were cancelled after about 20 min. The waves had disagreed on the routed-slot union, so the line's
   down units waited forever.
   - So `route=wave` is correct only because every wave computes the same top-10 from the same tagged pairs, and
     it does.
   - A one-wave mutant is not a reliable must-fail mutant: the waves share the LDS id words, so one wave's write
     shows only when it lands last.
   - The knob value is removed (refused by `FusedKnobs`, tested).

  the compliant n07-17 runs in every verdict, but a compliant n01-09 repeat (`P15_MODES=insitu`, about 3 min of

  layers). Numerics cover delta, delta_ple and qsa at r1 and r4s. qsa / delta_ple run the same fused body and router;

- **No quick e2e number.** PLAN 14 asks for one per deployable lever. The N3b arms lose 1.4-8.1 % of the layer on
  both bases and nodes, every round, so an e2e run could only confirm a loss. It was not spent. If a future lookback
  combination with these knobs wins in situ, it goes through the quick harness then.
- **N3a and the MFMA form are not measured.** Section 1.3 gives the reasons.
