## 3. Clean refusals (crate: `src/rir/parse.rs`, `src/rir/validate.rs` only)

Well-formed rocKE IR the direct compiler does not lower is now `ROCKE_DIRECT_UNSUPPORTED` (falls back); text that is
not rocKE IR stays `ROCKE_DIRECT_PARSE`:

- op names: an unknown name in a rocKE dialect (`arith. math. vector. memref. tile. gpu. scf. cf.` + identifier) is
  unsupported (`op "tile.tagged_poll" is not lowered by the direct backend`); other names stay PARSE;
- `tile.inline_asm` other than the empty `"=v,0"` pin (any template, any number of results) is refused in validation
  before the arity check (it was MALFORMED for zero / several results);
- `inreg` parameters (kernarg preload) are refused: they were silently ignored, which would have dropped the lever
  without a trace;
- unknown kernel attributes, `agpr_alloc` ranges other than `[0, 0]`, unsupported kernel argument types, non-global
  pointer address spaces, pointers to vectors (`ptr<vec<i32x8>,global>`), and unknown element types;
- a kernel symbol the ELF writer cannot emit (outside `[A-Za-z0-9_.$]` or > 1024 bytes) is refused at the start: the
  fused MoE r4 build's name holds `combinebase-1`, which failed late as `ROCKE_DIRECT_ELF` (no fallback);
- `comgr_fresh_process` (COMGR history policy) is accepted as a no-op: direct output depends on the IR text only.

New Rust test `rir::validate::tests::rocke_ir_the_direct_backend_does_not_lower_is_unsupported` covers every case on
gfx950 and gfx1151, plus the PARSE cases that must stay PARSE.

## 4. Framework knob (Python)

- `rocke.helpers.compile.request_code_object_backend(kernel, backend)` / `requested_code_object_backend(kernel)`: a
  per-kernel request stored as a Python attribute of the `KernelDef` object, not a kernel attribute, so IR text,
  serialization and LLVM lowering never see it. `compile_kernel(code_object_backend=None)` takes the mark, then
  `ROCKE_CODEOBJ_BACKEND`, then COMGR; an explicit argument wins.
- `qwen38_mono.framework.FrameworkKnobs.code_object_backend` (default `""`, validated, not in `suffix()`):
  `build_layer_kernel` marks the kernel when it is set. A refused build compiles with COMGR and says so
  (`artifact.code_object_backend == "comgr"`, `artifact.direct_fallback` = the refusal).
- `qwen38_mono/direct_pilot.py`: `representative_builds()` (14 builds, below) and `neutralize_census`;
  tests `library/tests/test_qwen38_direct_pilot.py` (`Q38_DIRECT_STRICT=1` turns skips into failures).

## 7. Findings for R2 and the port

- The direct backend refuses kernarg preload (`inreg`): any `best_spec` / `kernarg_preload=8` build needs the
  preload implementation (research 2.2, 3-4 d) or a `kernarg_preload=0` direct arm.
- `moe_fused._guarded` names values from a module-global counter: rebuilding a fused-MoE kernel in the same process
  gives different LLVM value names (identity across separate processes holds). In-process A/B or identity tooling
  must compile one `KernelDef` per arm, or reset the counter.
- Kernel names with `-` (knob value `-1`) cannot be direct symbols; R2 either maps names or keeps the refusal.
- The scaled-MFMA probe's pointer-to-vector argument stays on COMGR (probes are not on the serving path).
