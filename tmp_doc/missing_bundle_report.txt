KNOWN ISSUE: Reduction bundles capture but fail to load (114 tests)
====================================================================

The 114 Reduction tests (38 × Fp32/Fp16/Bfp16) DO capture to disk —
graph JSON files exist. But the bundle loader fails to register them
at load time with:

  [json.exception.out_of_range.403] key 'outputs' not found

Root cause: serialization schema inconsistency in hipdnn.

Most ops serialize tensor UIDs in nested objects:
  "inputs":  { "x_tensor_uid": 1, "scale_tensor_uid": 4 },
  "outputs": { "y_tensor_uid": 0 }

But ReductionAttributes serializes them as flat fields:
  "in_tensor_uid": 1,
  "out_tensor_uid": 0

The bundle loader expects the nested inputs/outputs pattern for all
ops and throws when it can't find the "outputs" key.

Fix location (hipdnn):
  projects/hipdnn/flatbuffers_sdk/include/
    hipdnn_flatbuffers_sdk/utilities/json/ReductionAttributes.hpp
  Lines 26-32: to_json() writes flat in_tensor_uid / out_tensor_uid
  instead of nested inputs { } / outputs { } objects.

Fix options:
  1. Update ReductionAttributes to_json/from_json to use nested format
     (aligns with all other ops — preferred)
  2. Make the bundle loader handle both flat and nested formats
     (more defensive but masks the inconsistency)

Impact: These bundles are noise — they log errors during bundle
discovery even when running unrelated tests (e.g. batchnorm).
Until fixed, consider excluding Reduction bundles from the capture
directory, or scoping --gd to specific subdirectories.
