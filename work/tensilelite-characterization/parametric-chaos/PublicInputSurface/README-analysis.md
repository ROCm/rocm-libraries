# README: Parametric-Chaos Run-1 Public-Input Surface Analysis

## What this directory contains

This directory (`PublicInputSurface/`) holds the assembled deliverables for Run-1 of the parametric-chaos characterization workflow applied to TensileLite. The workflow characterizes branch predicates in terms of their public inputs (CLI args, YAML keys, global parameters, environment), builds a solver-verified domain model, and optionally reifies the analysis as pytest-pinned unit tests.


**Critical**: do NOT pass `--cov=Tensile.something` (dotted module); if you need coverage use `--cov=Tensile` (the directory path). The nanobind rocisa extension causes SIGABRT if the coverage plugin tries to import the module via dotted name.

### Re-running solver analysis

Each Solve fragment was produced by:
1. Encoding the predicate as a z3 Bool/Int formula
2. Calling `z3.solve()` to find SAT witnesses
3. Running CrossHair on a pure-helper function extracted from the predicate
4. Verifying witnesses against the real argparse setup or real code in-container

Example for Tensile.py:529:
```bash
docker exec -w $PROJ tl-char python3 - <<'PY'
import z3
altFormat = z3.Bool("altFormat")
n = z3.Int("n")
pred = z3.And(z3.Not(altFormat), n != 1)
bounds = z3.And(n >= 1, n <= 3)
s = z3.Solver()
s.add(bounds)
s.add(pred)
print("SAT:", s.check())
m = s.model()
print("witness:", m[altFormat], m[n])
PY
```

## Static / solver / runtime split

| category | branch count | examples |
|---|---|---|
| fully-static (pure CLI/YAML) | 9 | Tensile.py:529, :526, :534, :239; GlobalParameters.py:659 |
| runtime-dependent (isinstance / nodeType) | 9 | Configuration.py:534, :579, :673, :692, :218, :230, :224, :730, :630 |
| runtime-env (filesystem / OS state) | 2 | Tensile.py:536 (os.path.exists), Tensile.py:409 (file content) |

"fully-static" means z3 can enumerate all relevant witnesses with bounded integer domains. "runtime-dependent" means the predicate truth depends on live Python object types or hardcoded source constants rather than user-visible inputs. "runtime-env" means the predicate is gated on filesystem or OS state at the time of execution.

## Workflow this output came from

The parametric-chaos dynamic workflow ran 6 agent phases sequentially:

1. **Census** — AST extraction of branch predicates from the source tree (branch_extractor.py)
2. **Slice** — backward slice from each predicate to its public input sources
3. **Domain** — domain specification: value sets for each input parameter
4. **Solve** — z3 + CrossHair SMT solving for SAT witnesses and classification
5. **Verify** — independent re-check of each branch's code + witnesses against real container
6. **Reify** — generate + run pytest tests pinning True/False witnesses for confirmed branches

The helper scripts live under:
```
/work/work/tensilelite-characterization/wf/parametric-chaos/
  branch_extractor.py
  harvest_constraints.py
  covering_array.py
  finalize.py            # driver-side deterministic recompute (below)
  gate.sh                # methodology-A 4-process no-regression gate
```

## Driver finalize (rigor: measure, do not inflate)

The workflow's LLM `Assemble` agent produced the narrative deliverables (this file,
`analyst_summary.md`, `validation_report.md`) but was observed to mis-handle the
**numeric / joined** deliverables: it truncated `branch_census.jsonl` to the 20 work-list
units, left the hypergraph sparse (some `Slice` agents returned their schema without
persisting a fragment), rewrote `constraints_harvested.jsonl` / `covering_array/model.json`
into ad-hoc schemas, and miscounted `scorecard.json`. The driver therefore re-ran the
deterministic helpers (`harvest_constraints.py`, `covering_array.py`) and `finalize.py`,
which recompute these from ground-truth fragments. Corrected, authoritative values:

- `branch_census.jsonl` — **full census, 221 records** (one per branch site across the 4 files);
  the 20 ranked work-list units are in `characterization_catalog.jsonl`.
- `branch_parameter_hypergraph.json` — **20 nodes, 20 edges**. Edges tagged
  `edge_source=slice-agent` (8, richer) or `census-defuse` (12, reconstructed deterministically
  from the extractor's intra-function def-use).
- `scorecard.json` — recomputed: 20 inventoried / 221 total branches, 2 constraints harvested,
  14-node op-surface, 15 SAT-confirmed witnesses, 0 unsat, 5 runtime-dependent (UNKNOWN),
  17 pairwise covering-array rows, 16 reified test files.

### Known blind spots (Run 1)

- **publicInputsMapped = 11/20.** The other 9 are runtime-dispatch guards (e.g.
  `nodeType == "Call"`, `isinstance(op, str)`) whose operand is a live parsed-AST node, not a
  public input — correctly classified `runtime-dependent`, never silently asserted.
- **domainsModeled = 19/20** (one unit's Solve fragment carried no domain).
- **Covering-array constraints not wired** into row generation (impossible combos may appear) —
  the stdlib pairwise fallback was used; ACTS/PICT/CodeQL/Daikon/Atheris were unavailable
  in-container (see `preflight.json` `optional_tools`, all `available=false`) and are deferred.
- All 16 reified test files (148 test cases) pass under `pytest -m unit`, confirmed by the driver.

```
docker exec -w $PROJ tl-char python $WF/finalize.py --root $PROJ --outdir $OUT \
```
